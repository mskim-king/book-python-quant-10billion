# 책 관리 사용법 (위키독스에 공개되지 않음)

## 저장소 구조
```
README.md        책 소개 (위키독스 첫 화면) — 자동 생성
TOC.md           목차 (위키독스 페이지 구조) — 자동 생성
structure.yaml   ★ 책 구조 정의 — 여기만 고칩니다
pages/           원고 (01-장.md, 01-1-페이지.md ...)
assets/          이미지
templates/       페이지 템플릿 (page, code, chapter)
tools/           설명 이미지 정의(diagrams.yaml)와 생성기
code/            예제 코드 (GitHub Actions 로 자동 실행 검사)
_관리/           사용법, 진행현황 (비공개)
```

## 기본 흐름
1. `structure.yaml` 수정 (장·페이지 추가, 순서·제목 변경)
2. `python generate.py --check` 미리 보기 → `python generate.py`
3. `pages/` 의 페이지에 내용 작성 (브랜치 `draft/주제명`)
4. 공개할 준비가 되면 페이지 맨 위 상태를 `🔵 검토 중` 또는 `🟢 완료` 로 변경
5. Pull Request → `main` merge → 위키독스 자동 반영

`main` 에 push 되면 GitHub Actions 가 2번을 대신 실행합니다.

## 동기화가 안 될 때
1. GitHub 저장소 `Settings > Webhooks` 의 Recent Deliveries 확인
2. 위키독스 `책 수정 > 깃허브` 에서 연결 저장소·웹훅 URL 확인
3. `지금 동기화` 버튼으로 수동 재시도

## 공개 규칙
- 상태가 `🟡 작성 중` 인 페이지는 목차(TOC.md)에 넣지 않아 **독자에게 보이지 않습니다.**
- 빈 틀까지 모두 보고 싶으면 `structure.yaml` 의 `show_drafts: true`.
- 진행 상황은 `_관리/진행현황.md` 또는 `python generate.py --status`.

## 페이지 순서를 바꾸면
`structure.yaml` 에서 순서를 바꾸면 파일 번호가 자동으로 바뀌고 내용은 그대로 옮겨집니다.

## 자동 점검 (GitHub Actions)
| 워크플로 | 주기 | 하는 일 |
|---|---|---|
| 구조 자동 생성 | main push 시 | 페이지·TOC·README 생성 |
| 갱신 점검 | 매월 1일 | 완료 페이지 중 최종 확인 기준일(structure.yaml 의 review_days) 경과 → Issue |
| 링크 검사 | 매월 15일 | 깨진 링크 → Issue |

## 갱신 주기
- 반기: `code/` 전체 재실행(GitHub Actions 코드 검사), 라이브러리 버전·데이터 소스 확인
- 변경할 때마다: CHANGELOG 기록

## 안전 규칙
- 토큰·비밀번호는 저장소에 커밋 금지
- 예시에는 실제 개인정보·회사 기밀을 쓰지 않음
