뉴스와 공시는 숫자보다 먼저 정보를 담고 있습니다. LLM을 쓰면 수천 건의 문서를 읽고 **요약·분류·감성 점수**를 매길 수 있습니다. 이 페이지에서는 공시·뉴스를 LLM으로 분석해 팩터 후보로 만드는 흐름과 주의점을 다룹니다.

## 요약

- 흐름: 문서 수집(OpenDART 공시 등) → LLM으로 **구조화된 정보** 추출(JSON) → 날짜별 점수 → 다음 기간 수익률과 검증.
- LLM 출력은 매번 조금씩 다를 수 있으므로 **형식을 고정**하고, 같은 문서를 여러 번 넣어 일관성을 확인합니다.
- 가장 큰 함정은 **시점**입니다. 문서가 공개된 시각 이후에만 점수를 써야 합니다.

## 전체 흐름

```text
① 수집     OpenDART 공시목록(접수일·시각 포함), 뉴스(발행 시각 포함)
② 추출     LLM: 문서 → {"사건 유형", "긍정/부정", "강도 1~5", "근거 문장"}
③ 집계     종목·날짜별 점수 (공개 시각 이후 첫 거래일부터 사용)
④ 검증     점수 상위·하위 그룹의 다음 기간 수익률 비교 (03장과 같은 방법)
⑤ 운영     새 문서가 들어오면 자동 추출, 이상 출력은 사람이 검토
```

## 추출 프롬프트 (예시)

```text
아래 공시를 읽고 JSON으로만 답해 줘.
{
  "사건유형": "실적|계약|증자|소송|지배구조|기타 중 하나",
  "방향": "긍정|부정|중립",
  "강도": 1~5 정수,
  "근거": "공시 원문에서 그대로 옮긴 한 문장"
}
판단할 수 없으면 방향을 "중립", 강도를 1로 하고 근거에 이유를 써.
[공시 원문]
...
```

## 주의할 점

| 위험 | 내용 | 대처 |
|---|---|---|
| 시점 오류 | 장 마감 후 공시를 그날 수익률과 연결 | 공개 시각 이후 첫 거래일부터 사용 |
| 학습 데이터 누출 | LLM이 이미 그 기업의 미래 주가를 학습했을 수 있음 | 모델 학습 시점 이후 기간으로 검증 |
| 출력 흔들림 | 같은 문서에 다른 점수 | 형식 고정, 여러 번 실행해 일치율 확인 |
| 환각 | 원문에 없는 내용을 근거로 제시 | "근거" 문장이 원문에 있는지 자동 대조 |
| 비용·속도 | 문서가 많으면 호출 비용 증가 | 작은 모델로 1차 분류, 중요한 문서만 큰 모델 |

[[TIP("근거 문장 대조")]]

LLM이 낸 "근거" 문장이 원문에 실제로 있는지 `in` 연산으로 확인하세요. 없으면 그 결과는 버리거나 사람이 확인합니다. 이것만으로도 환각을 많이 걸러 낼 수 있습니다.

[[/TIP]]

## 실무 체크포인트

- [ ] 문서의 공개 시각을 저장하고 그 이후에만 점수를 쓰는가
- [ ] LLM 출력 형식을 고정하고 일관성을 확인했는가
- [ ] 근거 문장이 원문에 있는지 대조하는가
- [ ] 모델 학습 시점 이후 기간으로 검증했는가
